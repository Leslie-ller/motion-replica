目标与结果

左边是 After Effects 渲染的目标，右边是 Agent 交付的动画。画面同步播放，打开时停在最后一帧，每轮在最后一帧停 1.5 秒。模型是 DeepSeek V4.1 Flash，经 Devin 客户端调用，禁用全部工具。三个结果是从同一框架的多次运行里挑出来的；浏览器窗口用的是当前代码，奖杯和叉号跑在加入“自动完整检查”之前。

怎么工作

看目标概览图、48 帧胶片图、每种颜色元素的运动曲线。
写动画主 Agent 用 set_ir 整体写入，或用 patch_ir（JSON Patch）局部修改。
子集校验超出子集直接拒绝，报错带 JSON Pointer，如 /layers/3/ks/p。
毫秒级预览常驻 headless Chrome + lottie-web；preview 给出 目标 / 当前 / 差异热图。
检查 Agent每次修改后快检；关键节点做完整检查，可放大任意 1 秒逐帧看。
交付进 AE最终动画用验证过的构建器编译成 AE 工程，逐帧渲染。

能精确回到 AE 的格式

Agent 写的是 Lottie 的一个子集：形状图层、路径、填充描边、嵌套组、图层变换关键帧和三次缓动。每一项都在 AE 里逐项验证过，构建器把 Lottie 缓动精确换算成 AE 的 speed / influence。

用看图代替分数

早期版本把像素指标、形状指标当作闭环反馈，Agent 会去优化指标本身：画面明显不对，分数依然很高。现在的反馈全部来自画面，检查 Agent 看不到 IR、看不到主 Agent 的对话，也没有分数可看。

只许用规定动作

客户端以 Ask 模式启动、禁用全部内置工具，模型只能在回复里写 JSON 动作。主 Agent 一旦发起工具调用，这次运行作废；检查 Agent 调工具或把工具调用写成文本，就换一个新会话重答。

预览与 AE 的还原度

迭代全靠预览，前提是预览和 AE 画出来的一样。lottie-web 和 AE 对同一份 Lottie 的求值并不完全相同：比如位置动画的空间切线与运动方向共线时，lottie-web 会丢掉切线、改成逐维插值，AE 始终沿空间曲线按弧长推进，遇到回弹、过冲就画得不一样。预览前把这类段的出切线沿法向推开 0.01 px，送进 AE 的动画不变；奖杯最差一帧的平均差从 0.77 降到 0.17（/255）。

局限

  • 结果不稳定。同一个任务多次运行，质量差别很大；同一框架下浏览器窗口跑了 3 次，其中一次面板偏出了画布。
  • 主 Agent 前期爱整段重写。第一次完整检查之前常常反复 set_ir 重写，检查之后才转成按意见 patch_ir。
  • 子集有边界。圆形旗帜要用路径一块块画出被圆裁切的扇形；子集不提供蒙版，Agent 算不出这种几何，只画出了方形旗帜。
  • 检查有成本。一次运行 13–21 分钟（上限 25 分钟），其中检查 Agent 占 6–10 分钟。

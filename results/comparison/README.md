# 闭环与一次生成的对照

同一模型（DeepSeek V4.1 Flash）、同一版代码，3 个任务，每个条件各 3 次。“一次生成”看到同样的开场图片，只交一次；“闭环”是带检查 Agent 的迭代（这批跑在加入自动完整检查之前）。交付的动画在 `irs/`，计算脚本 `tools/aspects.py`，逐次结果在 `aspects.json`。这些指标只在离线对比时计算，Agent 和检查 Agent 都看不到。

各条件的均值（↓ 越小越好，↑ 越大越好）：

| 任务 | 条件 | 有效 | 出现时机误差 s ↓ | 位置误差 ↓ | 面积误差 ↓ | 每帧可见一致 ↑ | 重合度（5 px 容差）↑ |
|---|---|---:|---:|---:|---:|---:|---:|
| 浏览器窗口 | 一次生成 | 3/3 | 0.142 | 0.125 | 0.205 | 0.967 | 0.872 |
| | 闭环 | 1/3 | 0.193 | 0.117 | 0.089 | 0.965 | 0.944 |
| 奖杯 | 一次生成 | 3/3 | 0.160 | 0.162 | 0.427 | 0.879 | 0.503 |
| | 闭环 | 3/3 | **0.038** | 0.225 | 0.561 | 0.939 | 0.386 |
| 叉号 | 一次生成 | 3/3 | 0.043 | 0.049 | 0.801 | 0.542 | 0.780 |
| | 闭环 | 3/3 | 0.064 | 0.055 | 0.608 | 0.563 | **0.840** |

所有运行都画出了目标的全部主要颜色，“颜色出现”一项没有区分度，表中省略。

- **奖杯的出现时机**：闭环 3 次（0.027 / 0.040 / 0.047 s）都好于一次生成的任何一次（0.227 / 0.080 / 0.174 s）。检查 Agent 的意见大多是“谁早了、谁晚了”，这一项改进最明显。
- **叉号的重合度**：闭环最差的一次（0.823）高于一次生成最好的一次（0.818）。
- **没有一致优势的方面**：奖杯上闭环的形状面积和重合度更差（第 3 次画出了画布）；叉号上出现时机略差；浏览器窗口闭环只有 1 次有效（另外 2 次检查 Agent 调用了工具，整轮作废；之后改成换会话重试，修复后的 3 次全部有效）。
- 每个条件只有 3 次，上面是这批运行的观测，不是显著性结论。指标是看过结果之后选定的。
